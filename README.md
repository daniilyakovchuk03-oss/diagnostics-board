# Доска диагностик

Показывает встречи онлайн-отдела по колонкам менеджеров. Данные берутся из amoCRM,
источник правды — этапы воронки. Отмечать статусы на доске руками нельзя, и это намеренно.

## Файлы

- `server.js` — сервер: опрашивает амо, принимает вебхуки, отдаёт данные доске
- `config.js` — соответствия полей, этапов и менеджеров. **Это единственный файл, который придётся править**
- `public/index.html` — сама доска
- `package.json` — зависимостей нет, базы данных нет

## Развёртывание на Railway

1. Загрузить эти файлы в приватный репозиторий на GitHub, сохранив структуру
   (`public/index.html` должен лежать именно в папке `public`)
2. Railway → New Project → Deploy from GitHub repo → выбрать репозиторий
3. В сервисе открыть Variables и добавить две переменные:
   - `AMO_DOMAIN` = `kursorschool.amocrm.ru`
   - `AMO_TOKEN` = долгосрочный токен из амо
4. Settings → Networking → Generate Domain, чтобы получить адрес
5. Redeploy

Токен хранится только в настройках Railway. В коде и в репозитории его нет.

## Настройка

Открыть `адрес-сервиса/setup` — страница покажет ID всех полей, воронок,
этапов и сотрудников. Эти значения переносятся в `config.js`.

## Вебхук в амо

amoМаркет → WEB HOOKS → добавить новый:

- адрес: `адрес-сервиса/amo/hook`
- события: «Сделка добавлена» и «Сделка изменена»

Существующие вебхуки не трогать.

## Проверка

- `/health` — жив ли сервер и сколько встреч загружено
- `/setup` — справочники из амо
- `/` — доска

Если доска пустая: проверьте, что в `config.js` заполнен `DATE_FIELD_ID`,
а у менеджеров проставлены `amo_user_id`. Сделки без заполненной даты диагностики
на доску не попадают — это ожидаемо.
